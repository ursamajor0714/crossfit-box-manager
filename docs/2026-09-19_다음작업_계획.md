## ① 코치 임명 / 해제 — on/off 버튼

### 왜

`직원등록` 으로 **켜는 곳만 있고 끄는 곳이 없다.** 코치가 그만두면 지금은 회원을 통째로
삭제하는 수밖에 없는데, 그러면 그 사람의 등록 이력·매출 기록까지 같이 사라진다.
권한을 전부 체크 해제해도 **관리자 화면 로그인 자체는 된다** (빈 화면으로 들어온다).

### 사용자 지시

> "코치 해제기능은 다시 코치 임명 누르면 사라지는걸로 on/off 버튼으로 만들어주고"

즉 **한 버튼이 두 상태를 오간다.**

| 지금 상태 | 버튼 | 누르면 |
|---|---|---|
| 코치임 | `코치 해제` | 직원 표시가 꺼지고, 관리자 화면에 못 들어온다 |
| 코치 아님 | `코치 임명` | 직원 표시가 켜지고, 열람 권한 탭이 나타난다 |

### 정해진 동작

- **회원 기록은 그대로 둔다.** 삭제가 아니다. 이름·연락처·등록 이력·매출 전부 남는다.
- **해제하면 관리자 화면 로그인이 막힌다.** 지금 로그인은 `is_staff=1` 인 사람만 찾으므로
  표시만 꺼도 자동으로 막힌다.
- **이미 로그인해 있는 세션도 그 자리에서 끊는다.** 권한 저장할 때 살아 있는 세션을 갱신하는
  코드가 이미 있으니 같은 방식으로 처리한다. 안 그러면 해제해도 12시간 동안 들어와 있다.
- **해제해도 권한 목록은 지우지 않는다.** 다시 임명하면 전에 주던 권한이 그대로 돌아온다.
  (그만뒀다 돌아오는 코치에게 처음부터 다시 체크하게 만들 이유가 없다)
- **버튼 자리** — 회원 상세의 `열람 권한` 탭 안. 단, 코치가 아닌 회원에게는 그 탭이 안 뜨므로
  `코치 임명` 버튼은 `기본 정보` 탭 아래 버튼 줄에 둔다.
- **사장님만 누를 수 있다.** 권한 저장과 같은 기준(`requireOwner`).

### 확인할 것

- 해제 → 그 사람 비밀번호로 관리자 로그인 시도 → 거절되는가
- 해제 → 회원 목록에 여전히 있고 `코치` 배지만 사라지는가
- 해제 → 매출·등록 이력이 그대로인가
- 다시 임명 → 전에 주던 권한이 그대로 돌아오는가
- 코치가 접속해 있는 중에 해제 → 다음 동작에서 바로 끊기는가

## ② 만료 임박 목록에서 바로 문자

### 왜

**필요한 부품이 전부 있는데 서로 안 이어져 있다.**

- 홈에 `⏰ 회원권 만료 임박` 목록이 있다 (7일 이내)
- 홈에 `🎂 생일` 목록이 있다 (7일 이내)
- 문자 발송 기능이 있다 (알리고)
- 문자 템플릿 기능이 있다

그런데 지금은 **목록을 보고 → 번호를 보고 → 개인 휴대폰으로 문자**를 보낸다.
만료 전 연락이 재등록률을 좌우하는데, 그 흐름이 손으로 끊겨 있다.

### 만들 것

- 만료 임박 목록에 **체크박스**와 `재등록 안내 보내기` 버튼
- 생일 목록에 같은 구조로 `생일 축하 보내기`
- 문자 템플릿 분류에 **`만료임박` · `생일`** 추가 (지금은 `체험` · `드랍인` 둘뿐)
- 템플릿 치환값에 **이름 · 만료일 · 남은 일수** 를 넣을 수 있게
- 보낸 것은 지금처럼 `발송 내역` 에 쌓인다

### 정해야 할 것 (만들 때 물어볼 것)

- 여러 명 한 번에 보낼 때 **같은 내용**인가, 사람마다 이름·만료일이 치환되는가 (후자가 자연스럽다)
- 보내기 전에 **미리보기**를 보여줄 것인가 (문자는 취소가 안 되므로 있는 편이 낫다)
- **같은 사람에게 이미 보냈는지** 표시할 것인가 (하루에 두 번 보내면 곤란하다)

## ③ 출석 체크 + 출석 보상

### 왜

시스템이 **"누가 회원인가"는 아는데 "누가 나오고 있는가"는 모른다.**
출석 관련 표가 아예 없다 (`count_usage` 는 횟수권 차감 전용이다).

크로스핏에서 이탈은 갑자기 오지 않는다. 2주 안 나오면 대개 안 돌아온다.
출석이 쌓이면 `2주 이상 안 온 회원` 목록이 나오고, 거기에 ②를 붙이면 이탈 방지가 굴러간다.

### 사용자 지시 — 출석 보상

> "출석은 5일 찍으면 하루 전체 기간에서 늘어나는 형식 괜춘하고"

**출석 5일마다 회원권 만료일이 1일 늘어난다.**

### 정해야 할 것 (만들기 전에 반드시 정할 것)

이 규칙은 **돈과 직결**되므로 아래를 정해 두지 않으면 나중에 숫자가 어긋난다.

| 정할 것 | 왜 정해야 하나 | 기본값 제안 |
|---|---|---|
| **5일은 누적인가 연속인가** | 연속이면 하루 빠질 때마다 처음부터라 가혹하다 | **누적** |
| **하루에 두 번 오면 몇 회인가** | 오전·오후 수업을 다 들으면 2회가 된다 | **하루 1회** |
| **상한이 있는가** | 3개월(90일) 동안 매일 오면 **+18일**이다. 20% 무료 연장인 셈 | **회원권당 상한을 두는 편이 안전** (예: 기간의 10%) |
| **횟수권 회원도 대상인가** | 횟수권은 만료일이 없어 늘릴 것이 없다 | **대상 아님** (또는 5일마다 +1회) |
| **재등록하면 남은 출석 수가 이월되는가** | 4일 찍고 재등록하면 그 4일이 아깝다 | **이월** |
| **환불할 때 늘어난 기간은 어떻게 치는가** | 보상으로 늘어난 날까지 환불해 주면 손해다 | **보상분은 환불 대상에서 제외** |

**상한이 가장 중요하다.** 상한이 없으면 열심히 나오는 회원일수록 요금을 덜 내는 구조가 된다.
사장님 판단이 필요한 부분이다.

### 만들 것 (뼈대)

- 출석 표 하나 (`attendance`: 회원 · 날짜 · 찍은 사람)
- **출석 찍는 화면** — 오늘 날짜로 회원 이름 검색 → 누르면 찍힘. 빨라야 한다
- 5회마다 만료일 +1일 자동 반영 (회원권 연장 기록에 사유를 `출석 보상` 으로 남긴다)
- 회원 상세에 **출석 이력**과 **다음 보상까지 남은 횟수**
- 홈에 **`2주 이상 안 온 회원`** 목록 → ②의 문자 버튼 연결

### 만들기 전에 스스로 물어야 할 것

> **수업마다 출석을 정말 찍을 것인가?**

반쯤 찍힌 출석부는 없는 것만 못하다. "2주 안 왔다" 가 거짓이 되고, 보상 일수도 틀린다.
찍을 자신이 있을 때 만든다.

## 어디에 있나

  이걸 안 끊으면 해제해도 하루 가까이 들어와 있게 된다
- **체크해 둔 열람 권한은 지우지 않는다.** 다시 임명하면 그대로 돌아온다.
  그만뒀다 돌아온 코치에게 처음부터 다시 체크하게 만들 이유가 없다

# 점검 도구 보강 (2026-09-25)

기준은 하나였다 — **이번에 도구가 놓치고 사람이 손으로 찾은 것.** 그게 전부 구멍이다.

## ① 고아 데이터 검사 (D)

부모가 없는 기록을 표 구조만 보고 **자동으로** 훑는다. 시나리오를 안 써도 된다.

설계하자마자 로컬에서 **`locker_history` 고아 16건 · 60,000원**이 나왔다.
없는 회원의 락커 요금이 매출에 잡히고 있었다. (9/18 삭제 수정 전에 돌린 QA 가 남긴 찌꺼기 — 지웠다)

이 검사가 있었으면 "회원 삭제하면 락커 매출이 남는다"를 시나리오 없이 바로 잡았다.
`member_id`·`locker_id`·`registration_id`·`uniform_id`·`reg_id` 를 쓰는 13쌍을 본다.
돈이 걸린 표면 **금액까지** 알려 준다.

> **운영도 확인이 필요하다.** 오늘 전까지 운영에도 옛 삭제 코드가 있었다.
> 락커 쓰던 회원을 지운 적이 있으면 그 요금이 아직 매출에 남아 있다.

## ② 입력칸이 실제로 쓰이는가 (A · T)

두 가지가 필요했다. 성격이 다르다.

**정적 (A)** — 화면이 보내는 항목을 서버가 `req.body` 에서 꺼내는가.
생년월일이 조용히 사라지던 것이 이 부류다.

만들면서 오탐을 세 번 잡았다.
- 경로를 앞 조각만 읽어 엉뚱한 라우트에 붙었다 → `+` 로 쪼개 조립하도록
- `JSON.stringify(memberBody)` 처럼 **변수를 넘기는 꼴**을 못 읽었다 → 위에서 그 변수를 찾아 읽도록
- 뒤로 900자를 훑다가 **다음 호출의 본문**을 끌어다 붙였다 → 같은 호출 안으로 제한

그리고 판정 기준도 틀렸었다. "이름이 코드 어딘가 나오면 통과" 로 했더니
주석과 `injury=?` 같은 SQL 컬럼명 때문에 그냥 통과했다. **`req.body` 에서 꺼내는 것만** 세도록 고쳤다.

**동적 (T)** — 사용자가 적은 날짜대로 그 달에 잡히는가.
정적으로는 안 잡힌다. 서버가 값을 받기는 받기 때문이다.
**이 검사가 오늘 찾은 '환불일이 무시되는 문제' 를 스스로 잡는다.**

## ③ 도구 자기 점검 (`lib/selfcheck.js`)

측정 도구가 거짓으로 실패하면 진짜 결함보다 나쁘다. 사람이 결과를 안 믿게 된다.

- **고정 날짜 금지** — 오늘 실제로 `2026-09-20` 때문에 홀딩 검사가 거짓으로 깨졌다.
  생년월일이나 '달력에 없는 날짜' 는 굳어도 되므로 제외하고, **'지금 근처' 날짜만** 잡는다.
  말일·윤년처럼 고정이어야 하는 줄에는 `고정날짜` 라고 적어 두면 넘어간다.
- **뒷정리 확인** — `QA` 로 시작하는 데이터가 남았는지, 고아가 새로 생겼는지
- **프로브 형식** — id·name·weight·run 이 다 있는지

프로브 11개의 날짜를 `kstDay()` 로 바꿨다. 이제 시간이 지나도 안 썩는다.

## ④ 비밀 검사 확장 + 커밋 직전 모드 (K · `check-staged.js`)

비밀 검사가 `.js`·`.ejs`·`.json` 만 봤다. **`.md` 를 안 봤다.**
그래서 배포 날 문서 세 곳의 비밀번호를 도구가 아니라 사람이 손으로 찾았다.

이제 문서도 본다. `localhost` 접속 문자열처럼 밖에서 닿을 수 없는 것은 뺀다.

**`node check-staged.js`** — `git add` 한 것만 1초 만에 훑는다. 서버 없어도 된다.
여기서도 오탐 하나를 잡았다. 예외 규칙이 '값' 이 아니라 '매칭 전체' 를 보고 있어서
`ADMIN_PASSWORD=진짜비밀번호` 가 앞글자 때문에 통째로 넘어갔다.

## ⑤ 배포 점검 (`check-live.js`)

배포 뒤 확인을 전부 손으로 했었다. 이제 한 줄이다. **읽기 전용 — 데이터를 안 건드린다.**

**배포된 화면 파일이 레포의 것과 같은지 글자 수로 대조**한다. 옛 파일이 남아 있으면 잡힌다.
그 외에 페이지 열림, 지운 API 의 404, 인증 없는 접근 차단, 보안 헤더.

지금 운영 기준 **45개 전부 통과.**
