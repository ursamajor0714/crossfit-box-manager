# 코치(부운영자) 등록과 열람 권한 (2026-09-18)

사장님 혼자 쓰던 관리자 화면을 **코치도 쓰되, 사장님이 허락한 곳만 보게** 만들었다.

## 한눈에

| 단계 | 어디서 |
|---|---|
| 코치를 만든다 | 회원 가입 신청서(`/contract`) 직원 작성란 > **직원등록** |
| 회원 정보에 들어간다 | 제출과 동시에 자동. 회원 목록에 **코치** 배지가 붙는다 |
| 볼 곳을 정한다 | 회원 상세 > **열람 권한** 탭 (사장님만 보이는 탭) |
| 코치가 들어온다 | `/admin` 에서 **이름 + 비밀번호** |
| 안 고른 곳 | "열람 권한이 없습니다." |

## 1. 직원등록 — 회원 가입 신청서

`기간제` `횟수권` 옆에 **`직원등록`** 칩을 넣었다. 1·2·3단계(기본 정보·본인 사진·운동 정보)와
약관·서명은 그대로 받는다. 코치도 사람이니 같은 정보를 받는 게 맞다.

직원등록을 누르면 **직원 작성란의 입력칸이 전부 잠기고 값이 비워진다.** 코치는 회원권 결제가
없으므로 요금제·기간·할인·금액·락커·메모를 받을 이유가 없다. 칩은 `<span>` 이라 잠금 대상이
아니어서 잘못 눌렀으면 기간제로 되돌릴 수 있다.

제출하면 **계약서가 남는 동시에 회원으로 바로 등록된다** (`members.is_staff = 1`).
회원권이 없어 관리자가 따로 등록할 게 없기 때문이다. 계약서는 곧바로 `등록됨` 처리된다.
같은 이름이 이미 있으면 409로 거절한다.

## 2. 열람 권한 탭

회원 상세의 `기본 정보 / 등록 이력 / 정보 수정` 옆에 **`열람 권한`** 탭이 붙는다.
**직원이면서, 보는 사람이 사장님일 때만** 나타난다. 코치는 이 탭 자체를 볼 수 없고,
서버도 `PUT /api/members/:id/permissions` 를 사장님 토큰이 아니면 403으로 막는다
(코치가 스스로 권한을 늘리는 것을 차단).

권한 키는 관리자 화면의 탭 하나에 하나씩 대응한다.

| 묶음 | 권한 |
|---|---|
| 홈 | 홈 |
| 매출 관리 | 매출 내역 · 가계부 |
| 회원 관리 | 회원 목록 · 등록 · 계약서 · 횟수권 · 홀딩 · 특별연장 · 가격표 · 계약서 작성 |
| 그 외 | 락커 · 시간표/신청 · WOD · 공지 · 문자 발송 |

사용자가 지시한 것은 홈·매출관리·회원관리 묶음이고, **나머지 탭도 같은 방식으로 넣었다.**
권한 목록에 없으면 그 탭은 아무 코치에게나 열려 버려 권한 자체가 무의미해지기 때문이다.

목록은 `backend/permissions.js` **한 곳에서만** 정한다. 서버 검사·화면 표시·권한 탭 체크박스가
모두 이 파일을 읽으므로, 탭을 추가할 때 한쪽만 고치고 다른 쪽을 빠뜨리는 일이 생기지 않는다.

## 3. 막는 방법 — 화면과 서버 두 겹

- **화면**: 권한 없는 탭은 흐려지고 자물쇠(🔒)가 붙는다. 눌러도 내용 대신
  "열람 권한이 없습니다." 화면이 뜨고, **데이터를 읽는 함수 자체를 부르지 않는다.**
- **서버**: `backend/middleware/perms.js` 가 라우터보다 먼저 돌면서 직원 세션의 요청만 검사한다.
  화면에서 탭을 숨기는 것만으로는 주소창이나 API 직접 호출을 못 막기 때문이다.

경로마다 규칙을 흩뿌리지 않고 **경로 → 권한 표 한 장**으로 처리한다. 다만 홀딩·횟수권 화면도
회원 목록을 읽으므로, 회원 조회는 `회원 관리` 묶음 중 **하나라도** 있으면 열어 준다.
안 그러면 홀딩 권한만 받은 코치의 화면이 깨진다. 요금표 조회(`GET /api/pricing`)는
등록·재등록·홈이 모두 읽으므로 검사하지 않는다.

권한을 저장하면 **이미 로그인해 있는 코치의 세션에도 바로 반영된다.** 다시 로그인할 때까지
옛 권한이 남지 않는다.

## 4. 코치 로그인

`/admin` 로그인 화면에 **이름 칸(코치만 입력)** 을 넣었다. 이름을 비우면 지금까지처럼
사장님 비밀번호로 들어간다.

코치 계정은 **회원 계정을 그대로 쓴다.** 새 계정 체계를 만들지 않았다 — 이미 회원 로그인
(이름 + 비밀번호, 기본값은 전화번호 뒷 4자리, 5회 실패 시 10분 잠금)이 있고 코치도 회원
테이블에 있기 때문이다. **직원으로 표시된 사람만** 관리자 화면에 들어올 수 있다.

### 남은 위험 — 첫 비밀번호가 약하다

전화번호 뒷 4자리는 경우의 수가 적다. 회원 화면이면 몰라도 **매출이 보이는 관리자 화면**에는
약한 값이다. 지금은 첫 로그인 때 "회원 화면에서 비밀번호를 바꿔 달라"는 안내만 띄운다.
관리자 화면 안에서 바로 바꾸게 하거나, 직원 등록 시 사장님이 초기 비밀번호를 지정하게 하는 편이
더 안전하다. 이번 요청 범위가 아니라 두었다.

## 실험용 더미데이터

`backend/scripts/seed-demo.js` — 실제 API를 그대로 호출하므로 매출·가계부 연결까지 평소와 똑같이 잡힌다.

```
node backend/scripts/seed-demo.js          넣기
node backend/scripts/seed-demo.js --clear  이 스크립트가 넣은 것만 지우기
```

들어가는 것: 코치 2명(권한을 서로 다르게), 회원 4명(기간제 2·횟수권 1·만료 임박 1, 락커 1개),
가계부 3건(물품판매 수입 · 임대료 고정비 · 공과금). **보충자료 필요 열을 보려고 인스타·사진·
운동방향성·부상을 일부러 군데군데 비워 뒀다.**

| 코치 | 비밀번호 | 볼 수 있는 곳 |
|---|---|---|
| 김코치 | `1111` | 홈 · 가계부 |
| 박코치 | `2222` | 홈 · 회원 목록 · 등록 · 홀딩 · 횟수권 · 계약서 작성 |

이름이 이미 들어 있으면 중복으로 넣지 않고 멈춘다. 지울 때는 회원·계약서·가계부를 이름과
상세 내역으로 찾아 지우므로 **직접 만든 데이터는 건드리지 않는다.**

# 로그인 방식 변경 — 비밀번호 하나로 (2026-09-18)

처음에는 로그인 화면에 `이름 (코치만 입력)` 칸을 두고 이름+비밀번호로 코치를 구분했는데,
사용자 지시로 **이름 칸을 없애고 비밀번호만 받는다.**

- **사장님 비밀번호**를 넣으면 관리자로
- **코치 본인 비밀번호**를 넣으면 그 코치로

## 첫 로그인이면 비밀번호 변경창이 강제로 뜬다

이름을 안 받으면 **비밀번호 하나로 사람까지 가려야 한다.** 기본 비밀번호(전화번호 뒷 4자리)를
그대로 쓰면 아무 4자리 숫자나 넣어 남의 계정으로 들어갈 수 있으므로, 처음에는
**비밀번호를 직접 정한 코치만 들어오게** 막아 뒀다.

사용자가 방향을 정했다 — **막지 말고, 들어오자마자 변경창을 띄우고 바꿀 때까지 계속 띄운다.**

- 전화번호 뒷 4자리로도 관리자 화면에 들어온다
- 들어오는 즉시 `비밀번호를 바꿔주세요` 창이 뜬다
- **바꾸지 않고 닫으면** 그냥 쓸 수 있지만, **다음에 들어올 때 또 뜬다**
- 바꾸면 그 자리에서 표시가 풀리고(재로그인 불필요) 다시는 안 뜬다

판단 기준은 `members.must_change_password` 와 "비밀번호를 아직 안 정했는지" 두 가지다.
새로고침해도 서버가 `/api/admin/me` 로 다시 알려주므로 화면을 껐다 켜도 유지된다.

새 비밀번호는 기존 회원 비밀번호 규칙을 그대로 따른다 — 8자 이상, 영소문자와 숫자 포함.
현재 비밀번호가 틀리거나 지금 쓰는 것과 같으면 거절한다.

### 함께 막은 것 — 코치가 남의 비밀번호를 바꿀 수 있었다

비밀번호 변경(`POST /api/member/:id/password`)은 `requireSelfOrAdmin` 을 쓰는데,
**관리자 토큰이면 어떤 회원 id 든 통과**하는 구조였다. 코치도 관리자 토큰을 갖게 됐으므로
그대로 두면 코치가 다른 사람 비밀번호를 바꿀 수 있다.
**코치 세션은 본인 id 일 때만 통과**하도록 좁혔다 (사장님은 그대로 전부 가능).

## 같은 비밀번호를 쓰는 사람이 둘이면

누구인지 정할 수 없으므로 **로그인시키지 않고 409로 거절**하고, 비밀번호를 바꾸라고 안내한다.
조용히 먼저 찾은 사람으로 들여보내면 남의 계정으로 들어가는 셈이 된다.

로그인 시도 제한(IP별 5회 실패 → 10분 잠금)은 그대로 적용된다.

| 안 바꾸고 다시 들어오면 또 뜬다 | ✓ |
