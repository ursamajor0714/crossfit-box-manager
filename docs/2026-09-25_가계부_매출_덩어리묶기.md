# 가계부 매출(+)을 세 덩어리로 묶고 내역은 팝업으로 (2026-09-25)

## 무엇을 바꿨나

가계부 왼쪽 매출(+) 칸이 건별로 한 줄씩 늘어나던 것을 **세 줄로 고정**했다.

| 덩어리 | 들어오는 항목 |
|---|---|
| 회원권 | 자동 집계 `회원등록`, 가계부에 직접 적은 `회원권` |
| 락커 | `락커` |
| 기타부수입 | 그 밖의 전부 — `드랍인`, `물품판매`, `기타`, 과거 `운동복` |

줄을 누르면 팝업(`ledger-group-modal`)이 뜨고 그 덩어리에 속한 **원래 건들이 날짜·항목·내역·금액**
으로 그대로 나온다. 가계부에서 직접 등록한 건의 `삭제` 버튼도 팝업 안으로 따라 들어갔다.

**지출(−) 칸은 손대지 않았다.** 지금처럼 건별로 나온다.

## 왜 이렇게 했나

- 항목 목록을 API에서 따로 받지 않는다. 덩어리 분류는 프론트의 `ledgerIncomeGroup()` 한 함수가
  `category` 값으로 판단한다. **백엔드는 한 줄도 안 바꿨다** — `/api/ledger` 응답을 그대로 쓴다.
- 팝업은 레포에 이미 있는 `.modal-bg` / `.modal` 패턴과 `closeModal()` 을 그대로 재사용했다.
  바깥 클릭·ESC 닫기가 공통 처리라서 따로 붙일 게 없었다.
- 팝업 안의 표는 기존 `renderLedgerRows()` 를 그대로 쓴다. 지출 칸이 쓰던 그 함수다.
- **기타부수입은 "나머지 전부"로 정의했다.** 목록을 열거하지 않았으므로 나중에 매출 항목이
  새로 생겨도 자동으로 여기에 들어간다. 합계가 새는 항목이 생기지 않는다.

## 덩어리가 0건일 때

세 줄은 **항상 보인다** (`0건` / `0원`). 눌러도 열리고 팝업에 `내역이 없습니다` 가 뜬다.
줄이 있다 없다 하면 위치가 흔들려서 그냥 고정했다.

## 바뀐 파일

| 파일 | 내용 |
|---|---|
| `frontend/views/admin.ejs` | 매출 표 헤더를 `항목 / 건수 / 금액` 3칸으로, `ledger-group-modal` 추가 |
| `frontend/public/js/admin-ledger.js` | `LEDGER_INCOME_GROUPS`, `ledgerIncomeGroup()`, `renderLedgerIncomeGroups()`, `ledgerGroupItems()`, `openLedgerGroup()`, `renderLedgerGroupRows()` |
| `frontend/public/css/admin.css` | `.ledger-group-row` (커서·호버) |

팝업을 열어둔 채 항목을 등록·삭제하면 `renderLedgerIncomeGroups()` 가 팝업이 열려 있는지
`classList.contains('open')` 로 확인하고 팝업 내용까지 같이 다시 그린다.
그래서 팝업에서 삭제해도 뒤 목록과 팝업이 같이 맞는다.

## 검증

로컬(도커 `cfbox-db` + `node backend/server.js`)에서 **실제 `/api/ledger` 응답**을 받아,
`admin-ledger.js` 원본을 `vm` 으로 그대로 실행해 렌더 결과를 검사했다
(함수를 흉내 내지 않고 파일을 실행하는 방식 — 9월 17일 `findRenewLockerId` 검증과 같다).

| 검사 | 결과 |
|---|---|
| 덩어리 줄이 정확히 3개 | ✓ |
| 세 덩어리 합계 = `income_total` (1,365,000) | ✓ |
| 회원권 1,230,000 / 락커 15,000 / 기타부수입 120,000 | ✓ |
| 팝업 줄 수 = 그 덩어리 건수, 이름이 전부 뜨는지 | ✓ |
| 팝업 삭제 버튼 개수 = `ledger_id` 있는 건수 (자동 집계 건에는 없음) | ✓ |
| 건이 하나도 없는 달(2026-01)에서 0원 3줄 + 팝업 빈 안내 | ✓ |
| 렌더된 `/admin` HTML 에 새 id·헤더가 모두 있는지, id 중복 없는지 | ✓ |

검사 스크립트는 임시 폴더에서 돌렸고 레포에는 남기지 않았다.

**브라우저에서 실제로 클릭해본 확인은 못 했다.** Claude in Chrome 확장이 꺼져 있어서 막혔다
(9월 17일과 같은 이유). 호버·팝업 열림 같은 눈으로 볼 부분은 직접 확인이 필요하다.

## 그대로 둔 것

- 지출(−) 칸 — 건별 목록 유지
- `/api/ledger`, 매출 내역 탭, 매출 엑셀 — 모두 그대로. 이번 변경은 가계부 화면 표시만이다
- 상단 `수입 합계 / 지출 합계 / 순익` 카드 — 그대로
- `pricing-modal` id 가 `admin.ejs` 와 `pricing-modal.js` 에서 두 번 생기는 것을 검사 중에
  발견했다. 이번 작업과 무관한 기존 상태라 건드리지 않았다

이번 작업과 무관하다.

## 새로 생긴 확인필요 1건 — 오탐이다

```
frontend/public/js/admin-ledger.js: ${cols} 를 escape 없이 넣는다 — 사람이 넣은 글자면 위험
```

`cols` 는 사람이 넣는 글자가 아니라 **코드에 박아둔 숫자 3 또는 5**(표의 칸 수)다.

```js
[['ledger-income-tbody', 3], ['ledger-expense-tbody', 5]].forEach(([id, cols]) => { ... })
```

`probes/i_injection.js` 는 변수 **이름** 만 보고 판단하는데, 안전한 이름 목록에
`cnt`·`count`·`num` 은 있고 `cols` 는 없어서 걸렸다. 도구 자체도 이 항목을 점수에 넣지 않는다.
**오탐을 피하려고 코드를 바꾸지는 않았다.** 값이 어디서 오는지가 코드에 그대로 보이는 편이 낫다.

## 자체 재검토에서 실제로 고친 것 2건

### 1. 효과 없는 CSS 한 줄 (지움)

`.ledger-group-row:hover { background: #fafafa; }` 를 넣었는데,
`admin.css:31` 에 이미 **`tr:hover td{background:#fafafa}`** 가 있다.
`td` 배경이 `tr` 배경을 덮으므로 내가 넣은 줄은 **화면에 아무 영향이 없었다.**
`cursor: pointer` 만 남기고 지웠다.

### 2. 모달을 남의 주석 아래에 끼워 넣었다 (옮김)

처음에 `ledger-group-modal` 을 `<!-- 락커 이력 수정 모달 -->` 주석과 그 모달 사이에 넣어서,
주석이 엉뚱한 모달을 가리키게 됐다. 락커 이력 모달 뒤로 옮기고
`<!-- 가계부 매출 덩어리 내역 모달 -->` 주석을 붙였다.

## 문제 없다고 확인한 것

| 검사 | 결과 |
|---|---|
| 새 전역 이름 8개가 다른 JS 파일과 겹치는지 (`calMonth` 같은 사고 방지) | 전부 `admin-ledger.js` 안에만 있음 |
