# 공개용 사본 작업 정리

작업일: 2026-09-26
결과물: https://github.com/ursamajor0714/crossfit-box-manager
작업 위치: `~/Developer/CROSFIT-GROVE-portfolio` (원본과 별도 폴더)

---

## 1. 목적

실제 운영 중인 박스 관리 도구를 **포트폴리오로 공개**하기 위해,
운영 데이터·배포 설정·업체 식별 정보를 제거하고 목업 데이터로 대체한 사본을 만든다.

## 2. 지킨 원칙 — 원본은 건드리지 않는다

원본(`~/Developer/CROSFIT-GROVE`)은 **렌더에 배포되어 코치가 매일 쓰는 중**이고,
`.env` 의 `DATABASE_URL` 은 운영 Neon DB 를 가리킨다.

따라서 원본을 수정하지 않고 **rsync 로 별도 폴더에 사본을 떠서** 작업했다.
작업 후 원본의 `git status` 가 깨끗한지, `.env` 와 `render.yaml` 이 그대로인지 확인했다.

시드 스크립트에도 안전장치를 넣었다.

> `DATABASE_URL` 이 localhost 가 아니면 실행을 거부한다.
> 원격 DB 에 넣으려면 `--allow-remote` 를 명시해야 한다.

실수로 운영 DB 에 `--reset`(전체 TRUNCATE)이 돌아가는 것을 막기 위한 것이다.

## 4. 목업 데이터 설계

`backend/scripts/seed-demo.js` — 회원 90명 규모의 "돌아가고 있는 박스"를 만든다.

### 원칙

- **화면마다 볼 것이 있어야 한다.** 개수를 채우는 것이 아니라 **상태를 배분**한다
- **날짜는 실행일 기준으로 계산**한다. 몇 달 뒤에 돌려도 "지금" 화면이 채워진다
- **난수에 고정 시드**를 쓴다. 몇 번을 돌려도 같은 회원 구성이 나와 스크린샷이 흔들리지 않는다

### 배분

| 항목 | 내용 |
|---|---|
| 회원 | 90명 (활성 78 · 휴면 12). 생일·메모·부상·목표 전원 보유 |
| 회원권 | 만료 임박 6 · 이달 만료 10 · 만료 휴면 12 · 횟수권 10 · 재등록 이력 22 |
| 락커 | 152칸 중 35칸 배정 + 배정 이력 |
| 홀딩 | 승인 12 + **처리 대기 3**, 특별 연장 3 |
| 신청 | 30건 (**대기 8** · 완료 22), 체험 28, 드롭인 24 |
| 계약서 | 16건 (**작성 대기 4** · 등록 완료 12) |
| 수업 | 시간표 14종 → 앞뒤 3주 86건 (휴관일 1건은 취소 상태) |
| WOD | 35건 (3주 전 ~ 1주 후) |
| 가계부 | 29건. 고정비 3건은 6개월 전부터 매달 자동 반복 |
| 문자 | 템플릿 6종, 발송 이력 42건 (성공·실패 혼재) |

**처리 대기 건을 일부러 남겨둔 것**이 핵심이다.
홀딩 승인, 계약서 처리, 신청 확정을 실제로 눌러볼 수 있어야 기능이 보인다.

## 5. 상호·로고 제거

공개용이므로 특정 업체를 식별할 수 있는 요소를 전부 없앴다.

### 문구 (36개 파일)

- `CROSSFIT GROVE` / `CrossFit Grove` / `크로스핏 그로브` → **CrossFit Box / 크로스핏 박스**
- 헤더 로고, 페이지 타이틀 6개, 푸터, **계약서 약관 전문(16곳)**, 문자 템플릿, PWA manifest
- 지점명과 히어로의 지역 표기 제거, 도메인 → `example.com`
- 패키지명·로컬 DB 이름 → `crossfit-box-manager` / `cfbox`

### 이미지 — 재생성

**텍스트 치환으로 해결되지 않는 부분이었다.** 로고와 상호가 이미지 안에 그려져 있었다.

| 파일 | 원래 | 처리 |
|---|---|---|
| `icon-192.png`, `icon-512.png` | 나무 + 상호 엠블럼 | 바벨 + `CROSSFIT BOX` 원형 아이콘으로 재생성 |
| `images/pricing-general.png` | 우상단 로고 + 상호 표기 | 같은 레이아웃·색으로 재생성 |

Pillow 로 그렸고, **스크래치패드 venv 에 격리 설치해서 시스템 파이썬은 건드리지 않았다.**

### 남겨둔 것

입력칸 placeholder 의 `예: 군자동` 3곳과 시드의 회원 거주지역은 **상호가 아니라 일반적인 동네 이름**이라 그대로 두었다.

## 6. 작업 중 발견한 버그 2개

시드를 만들고 **실제로 서버를 띄워 확인하는 과정에서** 드러났다.
둘 다 시드 쪽 문제였지만, 앱의 실제 동작을 몰랐으면 못 찾았을 것이다.

### 6-1. 락커 status 값이 앱과 달랐다

시드가 `status='occupied'` 로 넣었으나 **앱이 쓰는 값은 `'active'`** 였다.
(`lockers.js` 의 기본값이 `status||'active'` 이고, 연장 라우트는 `status !== 'active'` 를 막는다)

- 홈의 락커 사용 수가 **0으로 표시**
- 락커 연장·해지가 "배정된 락커가 아닙니다" 로 **차단**

### 6-2. 매출이 전부 오늘 날짜로 몰렸다

매출 집계는 **`created_at`(결제일시) 기준**이다(`stats.js`).
시드가 `created_at` 을 넣지 않아 기본값(now)이 들어갔고,
과거에 등록한 회원의 매출까지 전부 오늘로 잡혔다.

→ 등록·락커·계약서에 `created_at` 을 과거로 명시해 월별 매출이 실제 그 달에 잡히도록 고쳤다.

### 그 밖에 채운 것

첫 시드에는 **생일(`birth_date`)이 아예 없었다.**
홈의 "7일 이내 생일" 위젯이 항상 비어 있었고, 만료 임박 회원도 없어 만료 위젯도 비어 있었다.
두 위젯이 같은 회원으로 겹쳐 나오는 문제도 있어 인덱스를 떨어뜨려 배분했다.

## 7. 검증 방법

말로 확인하지 않고 **실제로 띄워서** 확인했다.

1. 로컬 Postgres 컨테이너 기동 → 시드 `--reset` 실행
2. 서버 기동 후 화면 6개(`/`, `/admin`, `/contract`, `/visit`, `/member`, `/wod-builder`) HTTP 200 확인
3. `/api/stats` 로 홈 위젯 값 확인 — 활성 78 / 락커 35 / 만료 임박 6명 / 생일 임박 5명
4. `/api/ledger?month=…` 로 월별 손익이 여러 달에 걸쳐 **흑자·적자 양쪽**으로 나오는지 확인
5. 렌더된 HTML 을 긁어 `grove` 문자열이 0건인지 확인
6. 서버 에러 로그 0건 확인
7. 원본 레포 `git status` 가 깨끗한지 확인

## 8. 재현 명령

```bash
cd ~/Developer/CROSFIT-GROVE-portfolio
docker run -d --name cfbox-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=cfbox -p 55432:5432 postgres:16-alpine
cp .env.example .env
npm install
node backend/scripts/seed-demo.js --reset
npm start
```

| 로그인 | 계정 |
|---|---|
| 관리자 · 계약서 | `0000` |
| 코치 (회원관리) | `김코치` / `1111` |
| 코치 (가계부) | `박코치` / `2222` |
| 회원 | 이름 + 전화번호 뒷 4자리 (시드 실행 시 예시 출력) |

정리할 때는 `docker rm -f cfbox-db`.
