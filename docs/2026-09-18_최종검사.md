# 오늘 작업 최종 검사 (2026-09-18)

기능 하나씩이 아니라 **여러 기능이 뒤엉킨 상태**까지 확인했다.
핵심 원칙: **API 응답을 믿지 않고, 원본 테이블에서 따로 계산한 값과 대조한다.**

## 검사 방법

| 검사 | 방식 |
|---|---|
| 백지에서 스키마 구축 | `DROP SCHEMA public CASCADE` 후 서버 기동 → 23개 테이블·락커 152개·가격표 6건 생성 확인 |
| 연결 검사 | DOM id ↔ HTML, 인라인 핸들러 ↔ 함수, 프론트 API 경로 ↔ 백엔드 라우트, 전역 중복 선언 |
| 계약 검사 | DB 컬럼 ↔ SQL, 응답 키 ↔ 프론트가 읽는 키, 요청 본문 ↔ 백엔드 구조분해, 함수 인자 수, 스크립트 로드 순서 |
| 표 정합성 | 레포의 모든 표에서 헤더 칸 수 ↔ `colspan` ↔ 행 셀 수 |
| 단위 | `node backend/utils/ledger.js` (고정비 펼치기·말일 보정) |
| 단위(DOM) | 락커 등록 모달 함수를 실제 소스에서 떼어내 가짜 DOM으로 실행 |
| 기능 E2E | 실제 API로 39개 시나리오 |
| **얽힘 검증** | 회원 3명·락커 3개(1개 반납+환불)·회원환불·드랍인·체험·가계부 6건을 한꺼번에 넣고 **달별 합계를 SQL로 따로 계산해 대조** (19개) |
| 엑셀·동시성·월경계 | 12개 |

## 검사에서 나온 진짜 버그 (전부 고침)

### 1. 없는 날짜가 만들어졌다 — `2026-02-31`

31일에 등록한 고정비를 2월에 펼치면 `2026-02-31` 이 나왔다. 숫자 합계는 맞지만,

- 화면에 없는 날짜가 표시되고
- **일별 조회로는 영원히 도달할 수 없다** (2월에 31일이 없으므로 그 고정비가 어느 날에도 안 보인다)

`dayInMonth()` 를 만들어 **그 달 말일로 당긴다.** 2월은 28일(윤년 29일), 4·6·9·11월은 30일.
자체 점검에 윤년 포함 케이스를 넣었다.

### 2. 앞 회원의 잠금 상태가 다음 회원에게 남았다

회원 상세 > 락커 등록에서 **연동 "예"** 를 누르면 날짜·기간 입력이 잠긴다.
그 상태로 닫고 **회원권이 없는 다른 회원**의 모달을 열면, 연동 질문 자체가 안 뜨는 대신
**입력칸이 잠긴 채로 열려 아무것도 고칠 수 없었다.**
모달을 열 때 항상 잠금을 먼저 푸는 것으로 고쳤다. 가짜 DOM 단위 테스트로 재현 → 수정 → 통과 확인.

### 3. 없는 달·날짜를 그대로 받았다

`?month=2026-13`, `?month=9999-99`, `?date=2026-02-31` 이 정규식을 통과했다.
결과가 비어 나오긴 했지만 고정비를 600개월까지 헛되이 펼쳤다.
`isValidMonth` / `isValidDate` 로 **달력에 실제로 있는 값인지**까지 확인한다.
`entry_date` 저장에도 같은 검증을 적용했다 (전에는 `2026-02-31` 이 저장됐다).

### 4. 숫자가 아닌 id로 삭제하면 500

`DELETE /api/ledger/abc` 가 DB 오류로 **500** 을 냈다. 404로 돌려준다.

### 5. 운동복 컬럼 제거 잔재

안 쓰는 전역(`filterUniform`, `sortUniformExpiry`)과 고아 주석이 남아 있어 정리했다.

## 검증한 관계식 (뒤엉킨 데이터 위에서)

- 달별 수입/지출/순익 = SQL로 직접 계산한 값 (7·8·9·10월 전부 일치)
- 가계부 수입(전체) = 매출 내역의 플러스 합
- 가계부 지출 − 직접입력분 = 매출 내역의 환불 합
- 7·8·9월 수입 합 = 전체 기간 수입
- 9월 1~30일 일별 지출 합 = 9월 지출 합
- 엑셀 안의 합계 = 화면 합계, 가계부 매출이 엑셀에 실제로 들어감
- 고정비 하나를 지우면 그 달 지출이 정확히 그만큼 줄고, 다른 달에서도 함께 사라짐
- 연말 넘어가는 고정비: 12월 등록 → 2027-01-20, 2027-03-20 으로 같은 날짜 유지

## 고치지 않고 보고만 하는 것

- **같은 락커에 동시에 두 명을 배정하면 배정 이력이 2건 남아 매출이 이중 계상된다.**
  기존 배정 API(`PUT /api/lockers/:id`)에 잠금이 없어서 생기는 일로, 오늘 작업이 만든 문제가 아니다.
  혼자 쓰는 시스템에서는 사실상 발생하지 않는다.
- **미래 달을 보면 고정비가 이미 나간 것처럼 합계에 잡힌다.** 실적이 아니라 예정으로 보이는 편이
  맞을 수 있다. 지금은 수입·지출 모두 같은 기준으로 펼치므로 순익 자체는 일관된다.
- **금액이 0원인 자동 매출 건은 가계부에 나오지 않는다.** 합계에 영향이 없어 그대로 둔다.
- 재등록 락커 제안은 `locker_history` 를 최신 200건까지만 본다.
- 동명이인이 있으면 락커 제안이 이름으로도 매칭될 수 있다 (`member_id` 우선, 이름은 보조).

# 추가 확인 및 수정 (공휴일 · 락커 중복 · 0원 매출)

## 공휴일 — 메인 화면 표시 확인

코드에 `공휴일` 이라는 이름은 없다. 같은 역할을 **`휴관일`** 이 하고 있다
(캘린더 일정 종류: `휴관일` · `오픈짐` · `이벤트`).

메인 화면의 달력 그리는 함수(`index.js`의 `loadCalendar`)를 **실제 소스 그대로 떼어내
서버 데이터로 렌더링**해서 확인했다.

| 확인 | 결과 |
|---|---|
| 휴관일 조회 API가 로그인 없이 열려 있음 | ✓ 200 |
| 휴관일 3일이 제목과 함께 메인 달력에 표시 | ✓ |
| 휴관일 칸이 `closed` 스타일(빨강)로 칠해짐 | ✓ |
| 오픈짐은 파란색으로 구분 표시 | ✓ |
| 공지 있는 날만 클릭 가능 | ✓ |
| 다른 달에는 안 나옴 | ✓ |

신청(JOIN US) 달력도 별도로 확인했다.

| 확인 | 결과 |
|---|---|
| 휴관일은 **수업이 있어도** 클릭 불가 (예약 차단) | ✓ |
| 평일은 클릭 가능 | ✓ |
| 휴관일엔 수업 점이 안 찍힘 | ✓ |

**회원 화면(`/member`)과 계약서·WOD 화면은 휴관일을 아예 쓰지 않는다.** 메인과 방문 화면만 쓴다.

### 발견 — 서버는 휴관일 신청을 막지 않는다 (미수정, 보고만)

화면은 클릭을 막지만 `POST /api/applications` 에는 날짜 검증이 전혀 없다.
화면을 우회해 직접 호출하면 **휴관일에도 신청이 그대로 접수된다** (실제로 확인).

```
POST /api/applications {"type":"드랍인","preferred_date":"2026-09-24"}  ← 휴관일
→ {"id":1,"message":"신청이 접수되었습니다"}
```

페이지를 열어둔 채로 관리자가 그날을 휴관일로 지정하면, 그 사용자는 그대로 신청할 수 있다.
막으려면 신청 접수 시 그 날짜에 `휴관일` 일정이 있는지 확인하는 검사 한 개를 넣으면 된다.
이번 요청 범위가 아니라 두었다.

## 락커 중복 배정 차단 (수정)

`PUT /api/lockers/:id` 에 잠금과 검사를 넣었다.

- 트랜잭션 안에서 `SELECT ... FOR UPDATE` 로 그 락커 행을 잠그고
- 이미 쓰는 사람이 있으면 **409** 로 거절한다

동시 요청 20개를 던져도 **배정 이력은 1건**만 남는다 (전에는 요청 수만큼 남아 매출이 그만큼 부풀었다).
반납 후에는 다시 배정된다.

## 0원짜리 자동 매출 제외 (수정)

서비스로 준 락커, 0원 등록처럼 금액이 0인 건은 매출 목록에서 뺐다.
합계는 원래 영향이 없었고 빈 줄만 쌓이던 것이라, 매출 내역·엑셀·가계부 모두에서 사라진다.

## 미래 달 고정비 — 확인 결과 이미 원하는 대로 동작

| 보는 곳 | 고정비를 어디까지 펼치나 |
|---|---|
| 가계부에서 그 달을 볼 때 | 그 달까지 (12월을 보면 12월분이 보인다) |
| 가계부 전체 기간 | **이번 달까지만** |
| 매출 내역 · 엑셀 (총 매출) | **이번 달까지만** |

실제 확인: 9월 고정수입 100,000을 등록하고 12월 가계부를 보면 12월분이 보이지만,
**총 매출에는 9월분까지만 잡혀 280,000** 으로 나온다. 미래분이 총 매출을 부풀리지 않는다.

## 함께 발견 — 홈 그래프와 매출 관리 숫자가 다르다 (미수정, 보고만)

같은 "이번 달 매출"인데 두 화면의 숫자가 다르다.

| 화면 | 이번 달 매출 |
|---|---|
| 홈 대시보드 (`/api/stats`) | 180,000 |
| 매출 관리 · 가계부 | 280,000 |

홈은 회원등록·드랍인 테이블만 직접 더하고, **가계부에 직접 넣은 매출과 락커를 세지 않는다.**
홈의 `월별 매출 추이` 그래프도 같은 이유로 가계부 매출이 빠진다.
맞추려면 홈 통계도 `buildRevenueItems()` 를 쓰도록 바꾸면 된다. 이번 요청 범위가 아니라 두었다.

# 마지막 두 건 수정 (2026-09-18 마감)

## 1. 휴관일에는 신청을 받지 않는다

`POST /api/applications` 에 검사를 넣었다. 그 날짜에 `휴관일` 일정이 있으면 **409** 로 거절한다.

```
휴관일로 지정된 날짜입니다 — 2026-09-24 추석 휴관
다른 날짜를 선택해주세요.
```

날짜 뒤에 조사를 붙이면 끝 숫자에 따라 은/는이 갈려서(`2026-09-24은`, `2026-09-22는`)
조사 없이 쓰도록 문구를 바꿨다.

확인: 휴관일 드랍인·체험 신청 둘 다 409로 막히고 DB에 0건, 평일과 **오픈짐 날은 정상 접수**된다.

## 2. 홈과 매출 관리의 '이번 달 매출'을 하나로 맞췄다

홈은 회원등록·드랍인 테이블만 직접 더해서 **락커와 가계부 매출이 빠져 있었다.**
홈 통계와 월별 매출 추이 그래프 모두 `buildRevenueItems()` — 매출 내역·가계부와 같은 집계 — 를
쓰도록 바꿨다. 테이블을 따로 더하던 쿼리 세 개가 사라졌다.

확인 (회원권 180,000 + 락커 15,000 + 가계부 물품판매 100,000):

| 화면 | 이번 달 매출 |
|---|---|
| 홈 대시보드 | 295,000 |
| 홈 월별 매출 추이 | 295,000 (3건) |
| 매출 관리 · 매출 내역 | 295,000 (3건) |
| 가계부 9월 수입 | 295,000 |

**네 화면이 같은 숫자를 낸다.** 그래프의 기준일이 회원권 시작일에서 **결제일시**로 바뀌었으므로
(매출 내역과 같은 기준), 지난 달 그래프 막대가 조금 달라 보일 수 있다.
