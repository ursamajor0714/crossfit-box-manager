# 패치노트 문구 전면 개편 (2026-09-18)

## 왜

첫 버전은 커밋 메시지를 거의 그대로 옮겨 적었다.

> SQLite → PostgreSQL 전환 / render.yaml 배포 설정 추가 / 계약서 테이블에 시작일·종료일 컬럼 추가

사용자 지적: **"야 이걸 어떤 일반인이 알아들어. 백엔드 프론트엔드고 뭔 소린지 모르잖아.
시스템 구성 코딩을 어떤 형식으로 바꿨습니다, 사용자에게 보이는 화면에서 어떻게 바꿨습니다 해야지.
내용도 너무 빈약하고"**

패치노트는 **개발을 모르는 사람이 읽는 글**이다. 커밋 메시지는 개발자끼리 쓰는 메모지 패치노트가 아니다.

## 바꾼 구조

항목마다 `changes` 하나였던 것을 **두 갈래**로 나눴다.

| 항목 | 내용 |
|---|---|
| `system` | ⚙️ 시스템은 이렇게 바뀌었습니다 — 무엇이 문제였고, 어떤 방식으로 바꿨는지를 비유로 설명 |
| `screen` | 🖥 화면은 이렇게 바뀌었습니다 — 눈에 보이는 변화 |
| `howto` | 👉 직접 눌러보세요 — 따라 할 수 있는 순서 |
| `author` | 작업자 (깃허브 아이디), 팝업 하단 우측에 표시 |

## 문구 원칙

- **기술 용어를 쓰지 않는다.** 검증 스크립트로 `백엔드`·`프론트엔드`·`SQLite`·`PostgreSQL`·`EJS`·
  `엔드포인트`·`라우트`·`CSP`·`HSTS`·`스키마`·`API`·`컬럼`·`모듈` 이 남아 있지 않은지 확인했다 (0건).
- **"무엇이 불편했는지"를 먼저 쓴다.** 예: "원래는 비밀번호 확인을 브라우저에서 했습니다.
  이 방식은 F12를 열어 값을 하나 바꾸면 비밀번호 없이도 관리자 화면이 열립니다."
- **비유를 쓴다.** 파일 하나에 저장 → "노트 한 권에 전부 적는 방식",
  코드 분리 → "서랍 없는 책상에 물건을 쌓아둔 것", DB 이전 → "창고만 통째로 이사".
- **보이는 변화가 없으면 없다고 쓴다.** "보이는 변화는 없습니다. 아침에 처음 들어갈 때 바로 뜹니다."

## 작업자 표기 — 깃 저자를 믿으면 안 됐다

처음에는 `git log` 의 저자 집계(`yeonjae951216` 22커밋 / `ursamajor0714` 5커밋)를 그대로 옮겨
항목마다 작업자를 나눠 적었다. 사용자의 정정:

> **"2.0.0부터 전부다 내가한거야... 1.0.0 하나빼고..."**

대부분의 커밋이 레포 주인 계정으로 올라가 있었을 뿐, 실제 작업자는 사용자였다.
**커밋 저자와 실제로 만든 사람은 다를 수 있다.** 크레딧을 적을 일이 있으면 깃 기록은 참고만 하고
사용자에게 확인해야 한다.

최종 표기:

| 버전 | 작업자 |
|---|---|
| 1.0.0 (최초 배포) | 연재의 대학원생 친구 |
| 2.0.0 ~ 현재 | `ursamajor0714 (유근호)` |
